# Прототипы пользовательского интерфейса

Эта папка содержит проверяемые UX/UI-артефакты, связанные с задачами проекта.

## Структура

Для задачи, которая добавляет видимый экран или компонент, новый пользовательский сценарий либо существенно меняет существующий экран, компонент или UI-поток, создавай папку:

```text
prototypes/<ticket-id>-<slug>/
```

Имя должно соответствовать папке задачи из `tickets/`. Например, для `tickets/1-task-manager/` прототип хранится в `prototypes/1-task-manager/`.

В каждой папке оставляй как минимум один проверяемый артефакт: например, HTML-прототип, wireframe или диаграмму потока. Добавь локальный `README.md` с краткой ссылкой на задачу и пояснением, как читать артефакт. Не оставляй результат только в переписке.

## Содержание и передача

Прототип должен показывать затронутые экраны, ключевые действия пользователя и состояния, влияющие на поведение: загрузку, успех, пустой результат, валидацию, ошибку и отмену — там, где они применимы. Укажи важные требования доступности. Не придумывай бизнес-правила: неподтверждённые решения помечай как допущения или открытые вопросы.

UX/UI-специалист передаёт оркестратору точные пути прототипа, краткое описание потока, состояния и открытые вопросы. Оркестратор передаёт этот контекст frontend-разработчику и UI-тестировщику. Для изменений без видимого пользовательского эффекта прототип не требуется.

Переиспользуемые общие пользовательские потоки описываются в `docs/USER_FLOWS.md`; детали конкретной задачи остаются в её папке прототипа.
